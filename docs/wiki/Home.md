# 使用与边界

Kizuna Pathfinding Framework 是独立的地面寻路库，不依赖 Meridian，也没有 Humanoid 或功法接线。

当前实现原方案的阶段 1 和阶段 2：纯 Java A*、移动能力、代价层，以及 Fabric 的近距离托管导航。
兼容模式（2b）、远距离分层规划、专用异步线程池、方块更新失效、群体导航、调试命令与客户端渲染尚未实现。
不创建 `client/` 模块。

| 目录 | 职责 |
| --- | --- |
| `core/` | Java 17 的只读体素网格、确定性 A*、移动规则、代价层、请求与结果 |
| `fabric/` | 1.20.1 世界快照、托管导航替换、服务端 tick 队列、移动执行与恢复 |
| `fabric/src/gametest/` | 隔离于发布 JAR 的真实游戏验收与测试宿主 |
| `docs/wiki/` | 文档的唯一编辑源 |

## 托管约定

库决定如何移动；目标由调用方的 AI 提供。调用方负责停用原版 Goal/Brain 中会驱动该实体的逻辑。
库不清空 AI、不保存接管状态。读档后，运行时单体接管需要宿主重新调用；整类登记通过服务端
`ServerEntityEvents.ENTITY_LOAD` 应用于已完成构造的实体，卸载时释放。区块实体重载、维度迁移和转换后的
新实体均走这个入口；构造期间不触碰导航，世界生成线程可以正常构造实体。

托管导航的原版 `findPathTo` 全部返回 `null`，原版 `startMovingAlong` 拒绝路径。
本库 API 成功规划后自动跟随路径；可从 `NavHandle.state()` 观察实际移动是否完成。
规划成功与到达目标是两个不同事件，`NavTicket` 只报告规划结果。

单体接管保留原来的导航对象；`release` 取消排队请求及移动，并恢复该对象。
未登记、未接管的生物完全使用原版导航。仅接受 Minecraft 自带的地面 `MobNavigation`；
其他导航类型和其他模组的导航子类会被拒绝，整类自动接管遇到冲突则记录日志并跳过。

## 已支持的移动

| 移动段 | 规划和执行 |
| --- | --- |
| `WALK` | 同高度八方向，含斜向；原版 `MoveControl` |
| `STEP_UP` | 八方向按实际顶面高差检查；不超过半格使用抬脚净空，更高台阶使用共享弹道 |
| `JUMP_UP` | 大于台阶上限、不超过跳高上限；先抬升再横移的速度弹道 |
| `DROP` | 八方向邻接落点、下降净空和实际安全落差上限；原版移动控制 |
| `LEAP` | 八方向跨越，可同时升高到跳高上限或降低到安全下落上限；共享阻力与重力模型 |
| `CLIMB` | 需声明攀爬权限，沿梯子或藤蔓等垂直相邻格运动 |
| `SWIM` | 需声明游泳权限，只做同高度水面邻接移动，不做水下三维搜索 |
| `DOOR` | 开门、通过已开门，或按权限破门；开木门不依赖 `mobGriefing`，破门需要该游戏规则 |
| 自定义 ID | 同一能力登记接口，附带每段独立的执行器工厂 |

`maxGap = 3` 表示方向上允许跨过 3 列、起落点相隔 4 步；斜向每个水平轴相差 4 格，
其基础代价仍不小于欧氏距离。同代价时固定方向顺序和队列序号保证结果确定，空旷对角线连续斜走。
移动上限以格为单位设置整数值，比较的是实际碰撞顶面的浮点高差，包括土径和半砖产生的额外高度。
网格按完整身体宽高检查空间，斜向检查两侧穿角及途中净空，跳跃检查整条离散弹道。
规划与执行共享实际起落点高度；移动执行不直接改坐标。

普通方块保存 Minecraft 实际碰撞箱；土径、耕地、半砖、地毯、灵魂沙和雪层均使用真实顶面。
节点仍采用方块列中心，不搜索同一格内的任意水平位置；每个身体覆盖列都须有支撑，
狭窄边缘和特殊形状可能被保守拒绝。门、水、可攀爬方块另行分类。
没有加载的区块视为封闭，不主动加载区块。遇到特殊实体物理或世界改变导致的执行偏差，按移动失败恢复。

## 请求调度与恢复

`planAsync` 在主线程排队，在后续服务端 tick 中读取快照、搜索并应用结果，通常下一 tick 完成。
这是一套延迟结果 API，当前不在后台线程读取世界或搜索。成功返回前保留正在执行的旧路径。
每个服务端共享工作预算，默认 4000 单位/tick，近距离范围默认 32 格；余量不足时请求留到后续 tick。
队列按优先级、提交顺序处理。新请求会取消该实体尚未完成的旧请求；队列默认最多 256 项。
A* 扩展到哪里才读取哪里的单元，本次规划内缓存；每扩展一个节点消耗一个单位，每 32 个首次读取
另占一个单位并向上取整。能力与代价层读取同一缓存，预算在读取前检查，不能通过自定义能力绕过。
`NavResult.readCells()` 和 `workUnits()` 分别报告读取格数与总工作量；当前仍不承诺远距离性能。

监听器否决一段时，在当前请求内屏蔽这条有向移动段，再从实际位置规划。
执行失败或卡住也会触发恢复；默认连续 40 tick 位移小于 0.05 格判卡住，单段另有总时限。
重算前等待落地，按 10、20、30、40 tick 递增退避，最多重算 4 次；找不到新路径时转为 `FAILED`。
新用户请求清空失败段和重算次数。每段开始前重新检查 `ProfileProvider`；参数改变则重新规划。

当前不做目标实体持续追踪、巡逻调度和方块更新事件驱动的路径失效；宿主可以提交新目标，
执行期间出现障碍则由卡住或落地失败触发恢复。远距离请求明确失败或拒绝，不回退到原版导航。
